What we’re working toward

We want to make intelligent systems useful on your terms. That means respecting who can access information, measuring whether a model actually improves, and connecting AI to software people can use.

Our projects are expressions of that objective. Secure retrieval, model evaluation, agent orchestration, and parallel development each explore a different part of the same question: how do we build AI that earns trust?

Who we’re here to work with

Organizations exploring AI for private knowledge. Engineering teams navigating changing data and complex workflows. Pilot partners with a specific problem and clear constraints.

We start by understanding the problem, defining what success looks like, and building a focused system that can be evaluated. We’re an early-stage team looking for thoughtful collaboration.

Guardian RAG

Working prototype

Enterprise RAG with security
built into retrieval.

Access-controlled retrieval, passage-level classification, PostgreSQL row-level security and tamper-evident auditing — filtering sensitive context before it ever reaches the model.

  • Secure AI
  • RAG
  • Access control
  • PostgreSQL
View source

The right answer, for the right person.

A policy assistant must respect the permissions of the person asking. Guardian RAG checks access before search, enforces it inside PostgreSQL, and checks again before returning an answer. The example interface shows an HR manager receiving a cited answer from a confidential section; the same question is withheld for other roles.

Question + role→Permission-aware search→Cited answer + audit

Capability demonstrated: secure retrieval, database access control, and auditable AI system design.

AutoFT

Experimental

Models that know when
they need to improve.

A self-maintaining LLM pipeline that detects performance drift, fine-tunes locally with QLoRA, and promotes a model only when it measurably outperforms production.

  • LLM ops
  • QLoRA
  • Evaluation
  • Model lifecycle
View source

Knowing when not to ship.

AutoFT watches real questions, statistically detects distribution drift, decides whether retraining is worth the GPU time, and fine-tunes on local hardware. A held-out evaluation compares the candidate with the incumbent. In its documented run, the promotion gate returned HOLD because the improvement was within measurement noise.

Capability demonstrated: model evaluation, automated fine-tuning, and production ML lifecycle engineering.

DocViewer

Mazen’s project

A workspace for the knowledge
behind the code.

A documentation viewer that brings Markdown, HTML, syntax-highlighted code, and Mermaid diagrams into one workspace — with split editing, document history, and CLI integration for agent-generated reports.

  • Developer tools
  • Markdown
  • Mermaid
  • Desktop workflows

Keep the thinking connected to the work.

Built by Mazen Sarwat Ismail, DocViewer makes engineering documents easier to read, edit, and navigate. Its documented features include a tabbed workspace, live Markdown preview, syntax-highlighted code, searchable navigation, Mermaid rendering with pan and zoom, HTML preview, and document history.

The React and TypeScript interface runs inside a Tauri desktop shell. A cached rendering pipeline brings together Markdown parsing, code highlighting, and diagram rendering. The desktop CLI can create a UTF-8 document and open it in the viewer; Claude Code live mode follows documents written by an agent without taking focus from an already-open workspace.

Files + CLI / agent output→Rendering + cache→Preview / source / split

Capability demonstrated: desktop product engineering, document rendering, developer workflow integration, and usable interfaces for technical knowledge.
